# Lean Plan Schema

An ordinary persistent plan uses exactly the sections below. Keep each section
semantic and concise. The current repository remains authoritative for local
implementation choices.

# <Feature Name>

## Outcomes

- State the observable results this work must deliver.

## Boundaries

- State non-goals, protected behavior, and approval limits.

## Likely Modules

- Name probable files or modules for orientation without freezing write scope.

## Known Dependencies

- Record only evidenced ordering, external, or ownership dependencies. Use
  `none` when no dependency is known.

## Acceptance

- State observable acceptance conditions and preserve relevant source anchors.

## Verification

- Name fresh checks that can demonstrate the accepted outcomes.

Do not add step-by-step edit instructions, code snippets, time estimates,
reviewer stages, executor selection, task DAG fields, or scheduler settings.
