## 四、详细设计

### 4.1 displayLabel

#### 4.1.2 设计机制

<a id="D-001"></a>
**D-001 · Behavior Contract · Accepted**

来源：[已批准请求](source.md)。沿用现有首尾空白去除行为；将剩余字符串中每一段连续 U+0020 替换为一个 U+0020。单个 U+0020 保持不变；内部制表符及其他字符保持原样，不合并跨越这些字符的空格段。

边界：纯函数及现有 UI 调用关系。不得扩大到所有空白归一化，不改变输入域、错误行为或首尾裁剪语义。下游评审必须保持这一边界；本次没有实施或规划授权。

#### 4.1.4 关键规则与边界

以下使用带转义的字符串记法，仅作设计推演。

| 输入 | 预期输出 | 检查点 |
|---|---|---|
| `""` | `""` | 空输入 |
| `" "` | `""` | 仅 ASCII 空格 |
| `"x"` | `"x"` | 单字符 |
| `"  a   b  "` | `"a b"` | 首尾既有处理与内部合并 |
| `"a b"` | `"a b"` | 单空格不变 |
| `"a\t\tb"` | `"a\t\tb"` | 内部制表符不变 |
| `"a  \t   b"` | `"a \t b"` | 制表符两侧独立合并 |
| `"a\u00A0\u00A0b"` | `"a\u00A0\u00A0b"` | 内部非 ASCII 空格不变 |
| `"a\nb"` | `"a\nb"` | 内部换行不变 |

#### 4.1.5 不变行为与验证

首尾空白字符集合、既有输入类型处理及错误行为以现有 `displayLabel` 为准；来源未给出其具体实现，不擅自定义新的集合或错误。上述非 ASCII 示例只涉及内部字符。函数保持纯函数，唯一 UI 调用关系不变。未来实现时应对照原函数验证这些既有语义，但此次没有执行实现测试。
