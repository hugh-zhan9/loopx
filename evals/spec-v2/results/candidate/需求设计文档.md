## 候选相同，输出投影不同

<a id="D-003"></a>
**D-003 · Data Contract · 演练方向已接受**（AC-001、AC-003、AC-004、AC-005、AC-006、AC-007）。候选读取复用 `TradingRestrictionRepository.ListTradingRestrictionCandidates(businessDate)` 的一次查询，条件如下；不得修改该查询或新增第二个来源。下游需用候选排除测试和投影测试守住边界。

| 维度 | 既有候选条件 |
|---|---|
| 市场与日期 | US 任务；任务日期等于 businessDate |
| 删除 | delete_time 为 null 或 zero |
| 状态 | 既不是 completed，也不是 no_action |
| 限制释放 | restriction_released_at 为 zero |
| 来源 | 任务记录；record-only RIC 不在任务来源中 |

政策通过 `tradingRestrictionDecisionForTask` 解析已有 handler 注册并校验 `TradingRestriction` 结果。注册或策略错误沿整体失败路径返回。政策返回 `Restricted=false` 时直接跳过，此时不对其存储代码应用“受限制任务空代码”错误规则。不得新增事件类型白名单；具体流程以[概要 D-002](概要设计.md#D-002)为准。

两条路径独立执行，下表不是一次 RPC 同时运行两个投影的顺序表。共同阶段截止于候选任务和政策判断，随后各自生成结果。

| 阶段 / 属性 | 新 RPC | 现有 Redis writer |
|---|---|---|
| 共同输入 | 同一候选合同及 handler 政策 | 同一候选合同及 handler 政策 |
| 分叉后的取值 | 存储的 task.Symbol | decision.Symbol |
| 变换 | 保留原字符串；不 trim、不大小写折叠、不规范化，不改用 normalized_underlying_symbol | 按既有 key 合同规范化 |
| 唯一与顺序 | 精确字符串去重，升序排序 | 规范化后去重，保留首次出现顺序 |
| 输出目的地 | reply.symbols；不访问 Redis | 既有 Redis 写入路径 |
| 示例 | AAPL、AAPL.US、AAPL.US → ["AAPL", "AAPL.US"] | 先按既有 key 合同取得规范值；fixture 未给具体映射，不猜测同一例子的 Redis 键 |

“空”指存储字符串为空串；不自行把空白串 trim 成空值。对于 `Restricted=true` 且 task.Symbol 为空的记录，整个 RPC 失败；既不能跳过，也不能改用政策结果或规范化字段。所有候选成功处理后才形成唯一列表；排序采用原始字符串自然字典序，不做地区化排序。输出规则没有改变持久化字段或旧 Redis 投影。

## 内部 RPC、错误与生成支持

<a id="D-004"></a>
**D-004 · Interface Contract · 演练方向已接受**（AC-002、AC-003、AC-006、AC-007、AC-008）。新增 `CorporateActionInnerService.ListTradingRestrictedSymbols`，保持 unary gRPC。服务层将 request 字段交给 biz，再将 biz 的结果映射为 reply；校验与选择只在 biz。下游需同时验证 biz 结果与客户端可观察的 wire 行为。

| 协议表面 | 合同 |
|---|---|
| request.business_date | string，必填；使用已有 validateRequiredDateLayout 验证 YYYY-MM-DD |
| reply.symbols | repeated string；来源与排序见 [D-003](#D-003)；无受限制任务时成功返回空列表 |
| 失败 | 返回 error，服务端不返回 reply；不允许部分 symbols 列表 |

日期校验发生在仓库调用前。使用来源明确给出的错误转换，不以常见 gRPC 习惯将其改成 `InvalidArgument`。

| 触发条件 | biz 内部错误 | 客户端 wire 结果 |
|---|---|---|
| business_date 缺失或空串 | CodeError 427012；business_date_required | gRPC Internal；message 为 error_code=427012 |
| business_date 非法，如 2026/09/07 | CodeError 427012；business_date_invalid | gRPC Internal；message 为 error_code=427012 |
| 仓库、注册、策略失败 | 沿用原错误传播 | 经过既有 inner 转换；fixture 未提供更具体映射，不新增统一化错误中间件 |
| 受限制任务的存储代码为空 | 整体失败；不得返回已收集结果 | 经过既有 inner 转换；具体内部错误类型及 wire code/message 待依据真实项目合同确认 |

日期错误内部 detail 不在 wire 上，客户端不能靠 business_date_required / business_date_invalid 区分这两类失败。其他路径未给出的消息不作为已确认合同。依赖若返回超时或其他错误，也沿既有错误转换；没有新增期限、重试或降级保证。

在 `TradingRestrictionUsecase` 上增加一个返回证券字符串列表与错误的查询方法，经 `Service` 和 `InnerUsecases` 注入。使用 service 消费端的小查询接口，保持 service → biz → repository / policy 的方向。方法与构造参数的精确签名要匹配真实代码，fixture 不足以确定其路径和上下文形状；这不授权新增包装服务或第二份政策实现。
