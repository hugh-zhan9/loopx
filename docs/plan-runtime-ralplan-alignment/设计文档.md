# plan runtime 按 ralplan 模式落地的设计文档

## 设计目标

在尽量不扰动 `clarify / build / review` 现有行为的前提下，把 `plan` runtime 升级为真实的多评审规划阶段。

## 文件级设计

### `src/workflow.mjs`

需要新增或扩展：

- plan 状态字段初始化
- plan 闭环控制逻辑
- planner draft 产物写入
- architect review 结果记录
- critic verdict 结果记录
- docs 阻塞检查

建议拆出独立适配层，例如：

- `src/plan-runtime.mjs`

职责：

- 抽象 Planner / Architect / Critic 的执行接口
- production 环境走真实 agent 编排
- test 环境走可预测 fixture 结果

### `src/cli.mjs`

需要扩展 `status` 输出：

- 当前规划轮次
- architect review 状态
- critic verdict
- docs 缺失情况

同时需要补充 `plan` 命令参数：

- `--direct`
- `--interactive`
- `--deliberate`

### `test/workflow.test.mjs`

需要新增：

- plan happy path
- critic iterate path
- docs 缺失阻塞 path
- docs 中文内容阻塞 path
- status 输出断言
- adapter 驱动的 deterministic review path

## 产物设计

### canonical 产物

- `.loopx/plans/prd-<slug>.md`
- `.loopx/plans/test-spec-<slug>.md`

### review evidence 产物

建议增加：

- planner draft evidence
- architect review evidence
- critic verdict evidence

至少要能让 status / debug 明确看到每轮结果，而不是只剩最终 state。

### 中文 docs 产物

固定目录：

- `docs/<slug>/`

固定文件名：

- `架构文档.md`
- `设计文档.md`
- `测试计划.md`

## 流程设计

1. 读取 source-of-truth spec
2. 生成 planner draft
3. 记录 `plan_current_iteration=1`
4. 执行 architect review
5. 执行 critic gate
6. 若 critic != approve：
   - iteration + 1
   - 返回 planner revision
7. 若 critic = approve：
   - 检查 canonical 产物
   - 检查 `docs/<slug>/` 三份中文文档
   - 全部满足后结束 `plan`

中文 docs 建议在每轮 planner revision 后重写，最终以最后一轮 approved 内容为准，避免内部 draft 与 docs 最终产物分叉。

## 失败语义

- Architect 未完成：不能进入 Critic
- Critic `iterate`：保持在 plan
- Critic `reject`：保持在 plan
- 任一 docs 缺失：保持在 plan
- 超过最大轮次：显式失败或残余风险结束，不能伪装成 approved

## 状态持久化建议

建议在 `state.json` 中增加：

- `plan_current_iteration`
- `plan_max_iterations`
- `plan_consensus_mode`
- `plan_deliberate_mode`
- `plan_principles_resolved`
- `plan_options_reviewed`
- `plan_architect_review_status`
- `plan_critic_verdict`
- `plan_docs_artifact_paths`
- `plan_docs_status`
- `plan_review_artifact_paths`
- `plan_acceptance_criteria_testable`
- `plan_verification_steps_resolved`

## 兼容性要求

- `skills/plan/SKILL.md` 已经是默认共识规划，runtime 必须与之对齐
- `skills/ralplan/SKILL.md` 保持兼容别名，不再维护独立逻辑
- 现有 `.loopx/plans/` 路径不变
