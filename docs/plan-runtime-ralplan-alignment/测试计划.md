# plan runtime 按 ralplan 模式落地的测试计划

## 测试目标

证明 `plan` runtime 已从轻量计划生成器升级为真实的共识规划闭环，并且完成判定严格依赖 canonical plan 与中文 docs 产物。

## 单元测试

### 1. 状态初始化

校验进入 `plan` 时：

- `plan_current_iteration=1`
- `plan_consensus_mode=true`
- `plan_architect_review_status=not-started`
- `plan_critic_verdict=none`

### 2. 产物路径

校验以下路径被正确记录：

- `.loopx/plans/prd-<slug>.md`
- `.loopx/plans/test-spec-<slug>.md`
- `docs/<slug>/架构文档.md`
- `docs/<slug>/设计文档.md`
- `docs/<slug>/测试计划.md`
- planner / architect / critic review evidence 路径

### 3. gate 校验

校验：

- Architect 未完成时不能进入 Critic
- Critic 非 `approve` 时不能完成
- 缺任一 docs 文件时不能完成
- docs 为英文占位内容时也不能完成

## 集成测试

### 1. happy path

- clarify 已批准
- plan 执行 planner -> architect -> critic
- critic approve
- 五份必需产物全部存在
- 状态标记为完成

### 2. iterate path

- critic 返回 `iterate`
- planner revision 再跑一轮
- 最终 approve
- iteration 计数增加
- review evidence 能反映多轮结果

### 3. docs blocking path

- critic approve
- 删除 `docs/<slug>/设计文档.md`
- 校验 plan 仍未完成

### 4. non-execution path

- plan 完成后不自动启动 build
- plan 完成后不自动启动 autopilot

## CLI 验证

校验 `loopx status <slug>` 输出：

- 当前规划轮次
- architect review 状态
- critic verdict
- docs 缺失列表

## 手工冒烟

1. 从一个已通过 clarify 的 workflow 开始
2. 运行 `loopx plan <slug>`
3. 观察是否存在真实的规划闭环状态变化
4. 检查 `.loopx/plans/` canonical 产物
5. 检查 `docs/<slug>/` 中文文档
6. 检查 review evidence 产物
7. 检查 `status` 输出
8. 检查没有自动进入执行阶段

## 退出标准

- 单元测试通过
- happy path 集成测试通过
- iterate path 集成测试通过
- docs blocking 测试通过
- docs 中文内容 blocking 测试通过
- CLI/status 验证通过
