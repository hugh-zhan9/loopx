# loopx 0.3.1

## Summary

`0.3.1` tightens the skill-first workflow surface. It removes the early owned runtime command path, carries requirement anchors through planning and execution, and adds stronger guardrails for surface-changing implementation work.

## Changed

- Added requirement anchor traceability from `clarify` and `spec` sources into `plan-to-exec`, `subagent-exec`, reviewer prompts, runtime context, and governance tests.
- Removed early runtime commands for plan/build/review/autopilot/archive orchestration from the public CLI, hooks, package contents, templates, and current docs.
- Simplified `loopx next` around skill handoffs instead of runtime command handoffs.
- Added high-risk surface-change planning requirements: Surface Inventory, caller proof commands, negative assertions, strict current product paths, historical/frozen path boundaries, and package/deploy/governance checks.
- Hardened `exec` and `subagent-exec` so removal, migration, compatibility, package, hook, template, installer, and public-doc changes require evidence before checkpoint approval.
- Updated the `subagent-exec` implementer, spec reviewer, and code quality reviewer prompts to pass and verify `SURFACE_CHANGE_CONTEXT` and surface-change evidence.
- Kept canonical skills and plugin-mirrored skills aligned for the release.
