# loopx 0.6.0

`0.6.0` makes loopx prompt-first: clear bounded work stays in the current
context, while planning, adaptive concurrency, independent review, and Git
disposition activate only from concrete triggers or explicit user intent.

## Changes

- Replaced the former fixed workflow path with six optional canonical intents:
  `clarify`, `spec`, `plan`, `exec`, `review`, and `finish`.
- Added one lean persistent plan format and one unified `exec` intent that
  derives serial or concurrent execution from current dependencies, write
  surfaces, verification boundaries, and host capabilities.
- Added an authoritative execution DAG with explicit inline, reviewed serial,
  and strict parallel-subagent profiles. Planned slices now use fresh leaf
  implementers, mandatory independent task review, isolated worktrees, and
  final Spec plus Standards review before integration.
- Added exec-owned Git isolation, protected integration, dirty-workspace safety,
  resumable manifests, worker-budget enforcement, and final combined
  verification for admitted concurrent mutations.
- Made independent review proportional to explicit review intent or concrete
  security, destructive, public compatibility, cross-task interaction, or
  conflict-reconciliation risk.
- Added one quiet completion check for fresh evidence, applicable spec
  synchronization, and narrowly qualified reusable project knowledge.
- Reduced `plan-to-exec`, `subagent-exec`, `parallel-subagent-exec`,
  `final-review`, and `fix-review` to explicit-only compatibility aliases.
- Removed legacy review ledgers, final-review reports, finish audits, executor
  selectors, and other mandatory ceremony from ordinary successful work.
- Added installed-product evaluation for direct, independent, strongly coupled,
  governed-escalation, spec-consistency, and memory-precision behavior.
- Added reproducible cross-version and three-way product comparison support with
  immutable refs, isolated installs, quality-first verdicts, provenance, token
  and latency reporting, and crossover execution order.
- Added the version comparison evaluation specification, including hard quality
  gates, experiment pinning, missing-metric handling, and release-claim rules.
- Corrected contradictory bundled-skill instructions:
  - TDD preserves existing user-owned implementation and uses characterization
    or regression evidence instead of deleting code to recreate a red phase.
  - `debug`, `tdd`, and `verify` activate explicitly or through an owning
    workflow rather than automatically capturing ordinary prompt-first work.
  - `fix` uses controller integration checks and proportional independent
    review instead of mandatory local and whole-diff reviewer ceremonies.
  - Debug examples no longer print environment secret values or authorize
    retry, timeout, or monitoring implementation from diagnosis-only requests.
  - Worktree setup runs only repository-documented commands and preserves
    confirmation around hooks, user-level writes, and external access.
  - CLI installation guidance now uses the canonical package-root skill source
    instead of the removed plugin skill mirror model.
- Added negative governance tests for these conflicting-instruction classes and
  synchronized all changed skill contract versions.
- Bumped the npm package and Codex plugin manifest versions to `0.6.0`.

## Evaluation Status

The release includes deterministic installed-product and cross-version
evaluation harnesses. No live provider performance number is claimed here:
release-quality version-comparison metrics require the pinned model, effort,
case matrix, crossover replicates, and quality gates documented in
`docs/loopx/specs/version-compare-evaluation.md`.
