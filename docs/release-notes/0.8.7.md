# loopx 0.8.7

- Add `design-review` as a bundled workflow skill between `spec` and
  `plan2exec`: it generates a standalone 概要设计 (high-level design) for
  mixed-audience review — what will be built, how it will work, and what
  will change — runs the review in presenter-declares/reviewers-challenge
  stance, and writes resolutions back into the detailed design's revision
  history. Open review items count as unresolved material decisions and
  block `plan2exec` through its existing STOP conditions.
- The review brief template carries a change-level header, a version table
  that records review-driven changes, a mandatory change inventory
  (storage / interfaces / touched code, with explicit zero-diff guarantees
  for untouched core paths), per-module 诉求 → 设计 → 规则与理由 sections
  with diagrams, per-stakeholder cooperation items, executable acceptance
  points, and a skippable technical appendix.
- `spec` 0.4.3: `一、修订历史` becomes a core section (the first draft is
  a version; every later revision appends a row in addition to inline
  notes), and the high-level layer now lives in exactly one place —
  designs passing `design-review`'s gate keep only 3.1 方案总述 + 3.6
  专项设计检查 inline and delegate architecture/flows/modules (3.2-3.5)
  to the standalone 概要设计.
- Housekeeping: `design-review` is registered across the bundled-skill
  list, the skill contract matrix (with a workflow root line guard), and
  the npm files allowlist; the spec matrix entry is synced to 0.4.3.

Note: the 0.8.6 tarball was published from a tree that already contained
part of this work; 0.8.7 aligns the published content with its release
notes.
