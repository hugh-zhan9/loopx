# 0.10.0

- Reduce the installed bundle to 21 skills. Use `debug` for diagnosis and
  requested repairs in place of `issue` and `fix`. Existing issue records remain
  readable; new records are optional.
- Move the trial implementations into `clarify` and `spec`. Keep overview and
  detailed design documents, but stop requiring a separate design proposal,
  alternatives table or discussion log. Small accepted choices need only a
  short record. Designs, plans and verification continue to check the original
  requirements and acceptance behavior.
- Include design review in `spec` and plan review in `plan2exec`; remove the
  standalone `design-review` and `plan-reviewer` entries. Ordinary plans no
  longer require independent review. Formatting suggestions do not block
  implementation or restart full review, and completed code is checked directly.
- Move `code-darwin` audits and its optional scanner into `refactor-plan`.
  Audit requests return findings without creating a plan. Refactor proposals can
  guide already authorized implementation directly. The scanner now recognizes
  `.mjs` and `.cjs` files.
- Remove the standalone `verify` entry and retain verification rules in the
  working agreement and shared evidence contract. Check the final state using
  completed command output; repeat checks only when relevant evidence changes
  or the repository requires it.
- Simplify skill descriptions and writing guidance. Let `codebase-spec` document
  the requested scope and update existing documents instead of requiring a full
  repository specification for every request.
- Document API behavior by business scenario using actual HTTP evidence, then
  apply `lancet` and `humanize-doc`. OpenAPI output is optional, and missing Ruby
  no longer makes `doctor` fail when that optional validation is unused.
- Preserve modified, foreign or unverified installed copies during upgrades.
  Retired entries are removed only when ownership, known files and unchanged
  contents can be verified. Update custom prompts that call removed entry names.
- Add installation regression tests and behavior exercises for skill selection,
  document updates, requirement coverage and review follow-ups. Exploratory
  results state their scope and do not claim measured token savings.

The npm package and Codex plugin both use version 0.10.0.
