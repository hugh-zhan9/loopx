# 0.11.0

## Release preparation and execution

- Add `release-readiness` for preparing and reviewing release runbooks, and
  following them for authorized rollout or resumption. Record branch scope,
  environment prerequisites, operation order, acceptance and rollback conditions.
- Keep prepared, deployed and accepted outcomes distinct. Refresh uncertain
  effects before retrying interrupted operations; a document does not grant Git,
  database, configuration or deployment permission.
- Include the skill in package and plugin installation, bringing the bundled set
  to 22 skills. Update the English and Chinese guides and skill-selection drills.
  No new execution runtime, CLI command or required implementation-plan stage.

## Existing skill improvements

- `debug` 0.4.1: build repeatable checks for the reported symptom, preserve the
  original case while reducing reproduction, and recheck it after repair. Continue
  bounded read-only investigation when reproduction is unavailable.
- `tdd` 0.3.9: derive expected results independently of the implementation. Explain
  why red-green and mutation sensitivity alone do not prove business correctness.
- `clarify` 0.5.2: resolve consequential domain-language conflicts and prepare
  focused questions for the actual decision owner when needed, without requiring
  a new questionnaire file or asking the current user to guess.
- `spec` 0.5.1: preserve business distinctions through field mappings, state
  transitions and examples. Load diagram guidance for relevant design changes.
- Share domain-language guidance between clarification and design, sharpen
  reference triggers, and remove conflicting mandatory diagnosis-record wording.

## Other changes since 0.10.1

- Add mutation-check guidance to verification and TDD.
- Require domain subpackages in the Go and Kratos skill guidance.
- Remove retired shared contracts and protect user content during installation.

## Verification

Add five focused decision drills for the existing-skill improvements and two
release preparation/resumption drills, plus packaged-reference checks. Scenario
validation is not evidence of live model behavior; these additions do not claim
measured quality or token-cost gains.

The npm package and Codex plugin both use version 0.11.0. Skill metadata versions
remain independent of the package version.
