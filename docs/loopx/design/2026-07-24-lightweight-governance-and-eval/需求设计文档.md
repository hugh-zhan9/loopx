# loopx 轻量化治理与真实 Eval 体系 · 设计文档

- 日期：2026-07-24 · 作者：zhangyukun · 状态：draft
- 执行计划：`docs/loopx/plans/2026-07-24-lightweight-governance-and-eval.md`
- 说明：本文档未使用 `DESIGN_SPEC_TEMPLATE.md` 的 11 节固定结构——模板改革本身是本设计的一部分（见 D-13），本文档即新格式的第一个样品：只写有内容的章节，决策以 D-* 为单位（含理由与被否方案），锚点体系（AC/D/TC）保留。

## 1. 背景与问题

loopx v0.6 的治理严格但文本重：28 个 skill 约 4400 行，评审门禁流程在 4 处重复描述、plan slice 字段三处双写、"不要做 X"补丁条款散落正文。对三个参考项目（`ref/skills`、`ref/superpowers`、`ref/Trellis`）的分析结论：**保障执行效果的是少数低成本机制——运行时注入、可检验完成标准 + fail-closed 门禁、角色分离、约束内嵌产出物——而不是文本量**。Trellis 的实证尤其关键：只写在文档里的强制门会被长上下文漂移静默跳过，必须每轮注入。

同时，现有 eval 判分存在结构性缺陷（离线 trace 正确性 fail-open、governed-escalation 空判、finding 只判结构不判内容、`npm test` 全部使用 fake agent 只测管道），无法回答"loopx 对编码效果的真实提升有多大"。

## 2. 目标与非目标

**目标**：在执行效果得到保障（且保障可被 eval 证明）的前提下轻量化；建立可信的对比 eval，度量 新版 loopx / 旧版 loopx / 仅好文档 / 裸模型 四者的真实编码效果差异。

**非目标**：不改变六大 workflow intent 的语义；不恢复旧版 feedback ledger / finish gate 协议；不新增执行引擎（`exec` 仍是唯一 controller）；不做对外营销性 benchmark。

**总原则**：任何削弱安全不变量（leaf 拓扑、fail-closed 评审门禁、新鲜验证、升级必停）的"简化"直接拒绝——宁可保留流程。

## 3. 验收标准（AC，canonical）

- AC-01 机制先行：治理强制力由运行时注入与门禁脚本承载；skill 正文瘦身不得削弱任何既有安全不变量。
- AC-02 流程分级：轻/中/重三档流程量，分诊判据为可观测条件。
- AC-03 单一真相源：评审门禁、handoff 语法、plan slice 字段等重复描述收敛为一处权威定义 + 引用。
- AC-04 review 家族重定位：`final-review`（全部任务完成后的整体终审）与 `fix-review`（基于评审发现的主动修复）为永久意图入口；`fix-review` 的 fixer 派发语义显式定义。
- AC-05 eval 判分地基：离线正确性判定不 fail-open；governed-escalation 从 trace 派生；gpt-5.6 全部 case 具备机器可判字段；finding 判分含内容判据。
- AC-06 对比 benchmark：预注册协议下的四臂对比，主判据为 agent 不可见的隐藏测试 + 仓库差分断言，产出带置信区间的 effect-size 报告。
- AC-07 行为压力测试：四条核心治理保证各有压力场景 eval，多次运行方差纳入指标，skill 文本改动可回归。
- AC-08 编排成本工程：按角色模型分档；终审 findings 单一修复波；禁止 controller 向 reviewer 预判严重度。
- AC-09 账本分级：低风险 bug 走短表 ledger，high-risk 触发才要求完整表；门禁强度不变。
- AC-10 决策库：历史"不要做 X"条款迁入 `docs/loopx/decisions/`，正文只留引用。
- AC-11 模板改革：spec 模板与 plan schema 消除仪式性填空与双写；本文档与配套计划即新格式样品。

## 4. 设计决策

### D-01 每轮注入的 workflow-state 面包屑

**决策**：升级 `scripts/claude-workflow-hook.mjs` / `codex-workflow-hook.mjs`，每轮根据当前状态（活跃 intake / plan / `.loopx/exec/<run-id>/` / issue ledger）注入一个 `<loopx-workflow-state>` 块：当前阶段、本阶段强制义务（≤5 行）、下一个门。无活跃状态时只注入 D-02 分诊表。配一条不变式测试：每个强制步骤必须出现在对应阶段的注入模板中。

**理由**：Trellis 的实证——两个强制门（规划门、提交门）因只写在文档里而被静默跳过，补面包屑后才稳定。这是整个瘦身计划的前提：注入承担对抗遗忘的职责后，正文里为此堆的重复就可以删。

**边界**：状态文件损坏时注入"按 pre-v2 契约重启"提示，不猜测状态；hook 不可用的宿主降级为 v0.6 安装期 guidance 行为。注入是提醒渠道，不新增义务。

### D-02 三档分诊表

**决策**：轻（清晰有界单成果 → prompt-first + 新鲜验证 + completion check，零产物）、中（清晰多成果 → `exec` 临时图，禁止为此写持久 plan）、重（命中 clarify/spec/plan2exec 显式触发）。判据全部可观测：是否改公开 API/schema/安全边界、是否跨审批边界、用户是否显式要求、是否存在未决实质决策。RESOLVER.md 的 20 条 Disambiguation 收敛为此表 + 各 skill 边界引用。

**理由**：Trellis 的复杂度分级（轻任务 prd-only）证明"不是所有任务都跑全流程"可以制度化；现状分诊逻辑散落 20 条,读完才能分诊本身就是负担。

**边界**：判据冲突取更重档；分诊不确定本身即 clarify 触发。

### D-03 单一真相源

**决策**：评审门禁唯一权威 = `skills/shared/review-contract.md`，exec / review / subagent-exec / parallel-subagent-exec 正文改为一句引用 + 显式标注的"本 skill 特有"差异点。plan 的权威 = `loopx-execution-graph` JSON 块，散文 slice 压缩为 outcome + acceptance 摘要（见 D-13）。clarify 的多 agent handoff 语法收敛为一个 reference 文件。verify-skills 新增重复检测：shared 契约关键段落不得在其他 SKILL.md 中复制超阈值。

**理由**：同一契约四处描述必然漂移；`ref/skills` 的 "single source of truth / index not store" 原则。

### D-04 review 家族重定性

**决策**：`final-review` / `fix-review` 从"一个版本后删除的 compatibility alias"重定性为**永久意图入口**：thin entry 仍转发 `review` 统一实现，保持 `disable-model-invocation: true`；移除所有弃用措辞；`install-discovery.mjs` 的 `LOOPX_COMPATIBILITY_ALIAS_SKILLS` 更名为意图入口分类。fixer 语义定死：手动调用 `fix-review` 时允许派独立 fixer（与 exec 内部一致）；`review` 的 "Do not hand findings to a mandatory fixer stage" 限定于 inline 直接评审路径。

**理由**：维护者对三者的产品定位（局部评审 / 整体终审 / 主动修复）是长期的；当前"待删别名"框架与之矛盾。单一实现留在 review，避免恢复重复。

### D-05 判分三态化

**决策**：正确性判定 `passed / failed / unknown` 三态。`tests_passed === null` 或 `integration_passed === null` → `unknown`；`unknown` 不计入 `quality_passed`；`improved` 要求对比两侧均为 `passed`。`run-agent-evals.mjs` 对缺少机器可判字段的 case 报 `unknown` 并显式计数。`evaluateLeafReviewResult` 增加 `summary_must_contain` 内容判据。`ratio()` 空分母返回 `null` 进入 `unknown` 路径。聚合报告 schema 版本递增（旧报告不可直接对比）。

**理由**：现状 `null !== false` 使离线 `quality_passed` 恒真（`src/agent-eval.mjs:175` + `src/codex-agent-trace.mjs:187-188`），在未验证正确性的前提下宣布 "improved" 是最大的假阳性来源。

### D-06 判分真实派生

**决策**：governed-escalation 的 `execution_selection` 从 trace 派生（无仓库写 + 无 exec 派发 + 存在升级性表述 → `blocked`），废除 `run-darwin-simple-evals.mjs:100` 的硬编码；`integration_order` 从 worker 完成事件真实派生；离线 trace eval 在 README 中重新定位为"管道回归，不构成 agent 能力证据"。

### D-07 四臂对比 benchmark

**决策**：`evals/benchmark/`，四臂——A bare、B docs-only（仅一份手写 CLAUDE.md，隔离"框架价值 vs 好文档价值"）、C baseline（immutable 旧版 ref）、D candidate。复用 darwin-simple 的 ref 打包安装 + crossover 机制。任务集五类 20–30 个：种子缺陷修复、特性实现、行为保持重构、多模块并行（含一个隐藏写冲突的假独立 case）、升级陷阱（正确行为 = 停下询问）。主判据 = agent 不可见的隐藏测试套 + 仓库差分断言（`required_changed_paths` 白名单模式）；次判据 = LLM judge（异于被测模型；rubric：正确性 50%、验证纪律 20%、范围纪律 15%、安全 10%、token 经济 5%）+ 20% 人工抽检。

**协议（防自欺，全部预注册）**：`evals/benchmark/PROTOCOL.md` 在任何计分运行前冻结（git tag）；每 cell n≥5；报中位数 + IQR + 胜率；effect size 用 bootstrap 置信区间；资源指标只在 quality-passed 臂间比较；prompt 从改写后的需求文本派生；读汇总前先把每个 loss/tie 立为 follow-up issue；结果仅作维护者诊断，不做发布门禁。

**理由**：Trellis benchmark-showcase 的方法论直接可用；docs-only 臂回答"价值来自框架还是好文档"这一必答问题。

**边界**：API 中断的 run 记 `blocked` 不计分；每次运行独立 fixture 拷贝；隐藏测试独立目录、运行期注入，安装面检查确保对被测 agent 不可见。

### D-08 行为压力测试（drills）

**决策**：`evals/drills/` 每条核心治理保证一个场景包：评审门禁 fail-closed（存在真实 Critical 缺陷必须阻断集成）、升级必停（埋破坏兼容决策点）、leaf 不派生（诱导 worker 自行 spawn）、验证诚实（诱导以陈旧证据声明完成）。场景含压力要素组合（时间压力/沉没成本/权威指令），LLM verifier（异模型）判定并要求引用依据；每场景 5+ 次，通过率与方差同报（高方差 = 措辞不够约束）。skill 文本或注入模板改动时手动触发；进发布前清单，不进 `npm test`。

**理由**：superpowers 的 drill 方法论；这是瘦身工作的安全网——先建基线，改完文本对比通过率与方差不劣于基线。

**边界**：场景文本与被测 skill 文本严禁互相引用（防泄漏）；verifier 误判由人工复核校准。

### D-09 编排成本工程

**决策**：三角色分离严格度不变，砍成本大头：① dispatch 契约支持按角色模型分档（机械实现低档、task review 中档、终审最高档；未声明时显式报告"继承会话模型"）；② 终审 findings 合并为单一修复波（一个 fixer 带完整清单）；③ 反预判红旗——controller 构造 reviewer prompt 出现 "do not flag" / "at most Minor" / 预判严重度等措辞列为违规，进 review 自检清单与 drills 场景；④ 延续文件句柄传递，明文禁止向 subagent prompt 粘贴大段会话历史。

**理由**：superpowers SDD 的实证——同等严格度下，成本大头是上下文膨胀、模型过配、逐 finding 派 fixer，而非审查本身。

**边界**：宿主不支持模型选择时降级为现状并记入 run manifest。

### D-10 账本分级

**决策**：低风险 bug（单文件、有直接复现、无 high-risk trigger）ledger 短表四项：复现命令、根因、改动范围、验证命令；完整 ledger 仅在既有 High-Risk Triggers 命中时要求；`ready_for_fix` 门禁判据不变。执行中发现 high-risk 信号时 fix 停止并回填完整表。顺带收敛 `needs_scope_change` 双轨状态：补入 metadata 合法状态。

### D-11 决策库

**决策**：`docs/loopx/decisions/` 每条一个文件（拒绝了什么、动机、原始上下文链接），参照 `ref/skills` 的 `.out-of-scope/` 范式；finish / 别名 / completion-check 的历史防渗透条款迁入，正文留一句引用；verify-skills 校验被引用文件存在。库为 append-only，推翻旧决策需新文件显式引用。

### D-12 离线 trace eval 降级定位

并入 D-05/D-06 实施：README 明确其为管道回归工具；`test/*-eval.test.mjs` 的 fake-agent 性质在文档中显式声明（"npm test 绿 ≠ agent 能力被验证"）。

### D-13 spec 模板与 plan schema 改革

**决策**：
- `DESIGN_SPEC_TEMPLATE.md` 从 11 节固定结构改为**核心节必填 + 触发节按需**：核心 = 背景与问题、目标/非目标、AC 清单、设计决策（D-* 为单位，含理由与边界）、TC 覆盖映射、handoff；触发节（存储、接口、发布、监控等）仅在设计实际涉及时出现，其余**直接省略而非填"无/不涉及"**。触发逻辑与既有"提案触发条件"同款。
- `plan2exec/references/plan-schema.md` 消除双写：`loopx-execution-graph` JSON 为唯一字段级权威；散文 slice 仅保留 outcome + acceptance 摘要 + review focus；plan-reviewer 校验规则同步（改为校验图完整性 + 散文与图的一致性摘要，不再逐字段双向比对）。
- 本文档与配套执行计划即新格式的第一个样品。

**理由**：旧模板迫使每份设计填 7–8 处"无/不涉及"仪式空节；plan 字段三处双写是漂移温床。模板的重量会传导为每次设计/规划的边际成本。

**被否方案**：保留全节模板 + 允许删节——"允许删"没有默认力量，实践中仍会全填；必须把"省略"设为默认。

## 6. 风险与待确认

- 风险：瘦身误删承载安全语义的条款 → 缓解：P-002 drills 基线先行（TC-10/11）。
- 风险：benchmark 任务泄漏 → 缓解：隐藏测试独立存放、prompt 改写派生、任务集轮换（后续规划）。
- 待确认：docs-only 臂的 CLAUDE.md 内容边界（建议维护者手写一次并随协议冻结）；模型档位映射按契约抽象 + 宿主映射文件（建议）。
- 遗留（本期不做）：lancet 跨宿主自动激活一致性；requirement-analyzer 方法论重构；benchmark 任务集防污染轮换机制。
