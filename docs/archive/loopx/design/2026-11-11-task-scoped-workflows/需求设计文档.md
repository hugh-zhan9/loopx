# 分层协作详细合同

权威需求与设计：[概要](概要设计.md)。D-001/D-002均来自本轮已批准方向及现有docs-first边界；实现细节由代理选择。Support lenses: none。

skill入口新增task-split；任务索引和brief默认写入docs/loopx/tasks/<requirement-slug>/，已有工作项/材料可复用。索引映射原始要求到task和需求集成验收，brief记录必要上下文、可决策范围、输入输出、依赖及其就绪依据、局部验收和交付结果。不是第二份PRD或runtime数据库。

clarify区分需求级与task级完成；spec保留共同合同的权威来源与局部设计；plan2exec映射当前task适用要求，明确父层剩余验收，不把其他task算作已完成或延期；exec在当前task范围完成单plan后回填交付，仍保留原内容归属恢复及Git约束。review检查局部与集成影响，不因task数自动增加审查轮数。

验证场景：TC-1大需求先划委托边界、串行结果交接；TC-2小任务不拆；TC-3人提供拆分原样承接并补缺口；TC-4非当前问题保留owner、当前必要问题阻断、共享决定传递；TC-5执行中拆剩余工作不重做已完成部分；TC-6父层验收不因各task完成自动通过；TC-7新skill在两宿主/包内可发现且升级不覆盖自定义；TC-8旧plan和现有直接执行入口兼容。以安装集成测试、现有全套确定性检查、场景材料走查及独立review覆盖，不把模拟模型输出当真实行为评估。
