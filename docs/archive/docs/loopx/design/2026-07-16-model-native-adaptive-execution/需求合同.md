# Model-Native Adaptive Execution 需求合同

Status: Approved
Approved on: 2026-07-16
Approved by: loopx maintainer / zhangyukun
Source proposal: `docs/loopx/design/2026-07-16-model-native-adaptive-execution/设计提案.md`
Source decision: 当前对话中维护者要求基于提案、现有代码和演进方向确定优化方案并进入 `spec`
Support lenses: architecture-designer, cli-developer, ddia:failure-review

## 1. 需求目标

- 收敛 plan 与 worker prompt，只保留 outcome、boundary、traceability、verification、
  evidence、review focus 和 stop condition，减少对强模型的实现微操。
- 将新 run 的 identity、state、evidence、review、Git、resume、completion 和 cleanup
  收归一个共享 execution kernel。
- 在不削弱 task review、Critical/Important 闭环和 final-review 责任的前提下，通过
  exact task delta、流式调度和可证明的测试去重降低 wall time 与上下文成本。
- 让 risk、prompt、model、adapter 和 scheduler policy 可版本化、可解释、可独立评估和回滚。
- 保留 current-contract run 的恢复路径、现有 expert skill aliases 和 public CLI 合同。

## 2. 非目标

- 第一代不自动启用 parallel，不启用生产 risk/mode 自动路由。
- 第一代不减少 delegated/parallel per-task review，不减少 final-review 六阶段责任。
- 不让启用 post-diff risk reclassification 的 run 原地写 invoking checkout。
- 不批量迁移历史 plan、state、review、finish 或 design artifact。
- 不新增 public skill、public CLI command/flag/JSON contract、第三方 runtime 依赖或固定 model ID。
- 不宣称可以强制互斥手工 Git、旧 binary 或其他不经过当前 facade 的外部 writer。
- 第一代不实现细粒度 target-ref/resource lease、跨 repo capacity coordinator 或持久 writer queue。
- 不承诺 native agent spawn exactly-once；只承诺结果不会被重复接受，变更不会被重复集成。

## 3. 已批准决策

| ID | 决策 |
|---|---|
| `R-001` | 采用 Decision Plane、Control Plane、Quality Plane 逻辑所有权；每个约束只有一个 accountable owner，其他模块只能是 enforcement owner 或 consumer。 |
| `R-002` | 新 run 共用 identity/state/evidence/review/completion/lease kernel；mode profile 另行固定 workspace/Git strategy、quality policy、adapter 和 effective concurrency。 |
| `R-003` | task contract 是 planning 的人类事实源；machine manifest 与 role prompt 由 compiler 生成，compiler 不猜 semantic dependency。 |
| `R-004` | 所有 unified writer mode，包括 controller inline，均在 runtime-owned worktree 中写入，并且 dispatch/assignment 前必须取得 adapter 或 runtime 可强制的 write-root boundary；仅有独立 cwd、standalone Git repo 或事后 delta 检查不构成写隔离。finish 前不修改 invoking checkout。无法提供该能力的平台不得启用对应 unified writer profile。 |
| `R-005` | current-contract in-place `exec` 仅作为 legacy resume 路径保留，不具备 post-diff adaptive quarantine 语义。 |
| `R-006` | changed-surface High-risk hard guard 是始终生效的安全不变量；其上的 risk/mode classifier 先 shadow、后 graduation。同一 run 的 observed risk 只允许单调升级，不允许通过重新分类跳过已经要求的 Gate。 |
| `R-007` | 第一代保留 per-task review-before-integration 和完整 final-review；review-turn reduction 是独立的后续实验。 |
| `R-008` | writer authorization 以 realpath-normalized Git common dir 为作用域，是 cooperative single-writer lease；unified correctness mutation 必须校验 append-only authoritative epoch claim。任何持有 lease mutex、state mutex 或 finish placement intent 的 owner，以及任何不具备 epoch fencing 的 legacy owner，在证明其 terminal 前都禁止 recovery/takeover；`current.json` 一类可变指针只能是可重建缓存。 |
| `R-009` | repo writer lease 与 provider/host agent capacity 是两套机制；第一代 writer 竞争返回 structured `busy`，不建立无 owner 的等待队列，也不承诺跨 repo 的原子 capacity coordination。 |
| `R-010` | 现有 `exec`、`subagent-exec`、`parallel-subagent-exec` 保留为 expert aliases，并逐步调用同一 facade；第一代不新增 public CLI 表面。 |
| `R-011` | parallel 与 v2 current-only 合同的替代按 clause 记录 `replaced`、`carried_forward`、`unchanged` 或 `deferred`，不得整项吞掉仍有效的安全语义。 |
| `R-012` | `wait-any`、early task integration、critical-path priority、test layering 和 review-turn reduction 分别 graduation，一次只改变一组变量。 |

## 4. Acceptance Criteria

| ID | 可验收要求 |
|---|---|
| `AC-001` | WHEN constraint registry 被验证，THEN 每个 hard invariant、quality contract、risk gate 和 heuristic 都有唯一 accountable owner、failure mode、enforcement、eval case；heuristic 另有 sunset condition。 |
| `AC-002` | WHEN 新 task contract 生成，THEN 它包含稳定 identity、outcome、AC/D/TC、create/modify/test surfaces、allowed writes、interfaces、semantic dependencies、exclusive resources、verification、evidence、review focus 和 residual risk；默认不含完整实现代码、2-5 分钟微步骤或重复 schema prose。 |
| `AC-003` | WHEN compiler 生成 manifest 或 role prompt，THEN 输出绑定 source/compiler/policy/prompt version 与 hash，只投影当前 role 所需约束；无法证明 dependency/write safety 时在 dispatch 前选择 concurrency=1 或拒绝，不从 prose 猜边。 |
| `AC-004` | WHEN inline-controller、delegated serial 或 parallel unified run 启动，THEN 它们使用同一 versioned run/task/evidence/review contract，并持久化不可在运行中静默切换的 generation、mode profile、workspace strategy 和 quality policy。 |
| `AC-005` | WHEN unified writer run 开始，THEN controller 与 workers 只在 runtime-owned write root 内写入，source Git common dir 对 leaf 只读，declared path 的 symlink/nearest-existing-ancestor 在 dispatch 前验证，adapter/runtime 对越过 write root 的文件与 Git mutation实施强制拒绝；invoking checkout 的 tracked bytes、index、HEAD、existing untracked/ignored placement-sensitive content 保持不变。能力无法证明时 profile unavailable 并 fail closed。 |
| `AC-006` | WHEN authoritative changed-surface guard 从真实 diff 发现未批准的 High-risk surface，THEN无论 classifier 是否处于 shadow，run 都进入 `decision_required`，停止新 dispatch/integration/finish并保留 owned worktree 与证据；批准后的新 requirement/design revision 通过 successor run 继续，不原地改写旧 run identity。 |
| `AC-007` | WHEN risk/mode classifier 处于 shadow，THEN它只使用带 evidence 的 requirement/repo/diff signals，输出稳定的 selected mode、risk、required/skipped gates 与 reasons；除 `AC-006` hard guard 外，不改变实际 executor、tree 或 baseline quality Gate。自动 routing/enforcement 必须分别 graduation。 |
| `AC-008` | WHEN同一 run 的 observed risk 从 Low 升到 Standard，THEN observed risk 与 recommended gates 只增加不减少；shadow 阶段实际 Gate 不低于 pinned baseline，enforcement graduation 后 actual required gates 也只能增加。WHEN 升到未批准 High，THEN按 `AC-006` fail closed。 |
| `AC-009` | WHEN两个 participating writer run 指向同一 Git common dir，THEN 最多一个取得 writer authorization，另一个返回 structured `busy` 且零 repo/run mutation；read-only run 不受该 lease 阻塞。 |
| `AC-010` | WHEN unified lease 被恢复或重新取得，THEN append-only authoritative claim 的新 fencing epoch 使旧 controller 的 state、Git、integration、completion 和 cleanup mutation 全部失败；旧可变 pointer 不得降低 authoritative epoch。legacy alias 也必须先经当前 facade 取得同一 authorization；任一 lease/state mutex holder、finish placement owner 或未实现 epoch fencing 的 legacy owner未被证明 terminal 时 recovery/takeover必须拒绝。 |
| `AC-011` | WHEN多个 repo 同时运行，THEN repo lease 互不阻塞；每个 run 的 leaf 数受本地 runtime/provider policy 有界限制，provider capacity/rate-limit error 形成 backpressure，controller 与 lease 不占 leaf slot；跨 repo 总 leaf 原子上限不在第一代保证内。 |
| `AC-012` | WHEN prepare 或持久 transition 中断后 resume，THEN caller-supplied stable run/operation identity 与 request digest 可定位同一 prepare intent，并且 source、manifest、repo、baseline、target/worktree、engine、policy、prompt、adapter、requested/observed model、authoritative epoch 和 active reservation identity 全部验证；mismatch fail closed。 |
| `AC-013` | WHEN native spawn 结果在 identity 持久化前丢失，THEN runtime 将 reservation 标为可检测的 orphan/uncertain dispatch且不接受未绑定结果；只有 inspect/cancel 证明原 worker terminal 后才允许有界 replacement，无法证明时 run 阻塞。已接受的 result、review、integration、completion 和 cleanup 不重复。 |
| `AC-014` | WHEN runtime 返回 `next_actions`，THEN controller shim 只执行带 reservation identity 的 create/wait/cancel/capture；`next -> reserve` 必须由 revision/request digest/selection token 绑定并在 state mutex 内重新验证。worker 保持 leaf-only，且 write-root enforcement 阻止其写 central state、source refs/objects、其他 worktree、integration、completion 或 write root 外路径。 |
| `AC-015` | WHEN task review package 生成，THEN 它只表示该 task 的 base-to-candidate tree delta，覆盖 tracked/staged/unstaged、untracked content、create/delete/rename、mode/symlink、actual-vs-declared paths 以及 report/verification hashes，不混入前序 task delta。 |
| `AC-016` | WHEN actual writes 越界或 review artifact stale/incomplete，THEN integration 被拒绝；Critical/Important 阻塞并要求 fix/re-review；Minor 可与 `Approved` 共存且不阻塞。 |
| `AC-017` | WHEN strict adapter 的 `wait-any` candidate 单独启用，THEN单个 task 完成后即可进入 scope-check/review，但 integration 仍保持既有 barrier/order；无法证明 worker isolation 的 adapter 连 wait-any 也不得启用。 |
| `AC-018` | WHEN独立的 early-integration rung 启用，THEN只有 review 通过、actual writes 不冲突、无 semantic dependency 且满足可交换性证明的 task 才可按完成事件 integrate；相同 source/manifest 仍产生相同 final tree。package child boundary commit 继续使用声明的稳定顺序，除非后续设计显式 supersede。 |
| `AC-019` | WHEN requested/observed model 或 adapter capability 不一致，THEN provenance 记录实际 identity；不满足 High-risk/final-review minimum policy 的 substitute 被阻塞或升级，不伪装为请求模型。 |
| `AC-020` | WHEN current-contract state 被打开，THEN按现有 path/schema 路由 legacy engine且不就地迁移；unknown schema 或缺失 compatible engine fail closed；pre-v2 state 继续不受支持。 |
| `AC-021` | WHEN existing skill alias 或 public CLI 被调用，THEN现有 command/flag、human/JSON、stdout/stderr、exit code、non-TTY 和 install surface 保持兼容；任何新 public mode/risk/explain 表面另行设计。 |
| `AC-022` | WHEN run success、blocked、interrupted、superseded 或 rollback，THEN只清理 manifest-owned 且 identity/fence 匹配的资源；blocked evidence 保留；run data owner-only、gitignored，trace 不含 secret、raw environment 或无关源码。 |
| `AC-023` | WHEN prompt/policy/model/scheduler candidate 进入 graduation，THEN一次只改变一个实验组，每个 replicate 先通过全部 P0 absolute gates，再比较 paired crossover baseline；任一严重回归阻止 graduation。 |
| `AC-024` | WHEN detailed design supersede 旧 parallel/v2 合同，THEN每个被影响 clause 及其上游 AC/TC 都有 successor disposition；未明确替代的 safety、review、recovery、Git ownership 和 dirty-worktree clause 默认 carried forward。 |
| `AC-025` | WHEN delegated serial 或任一 parallel unified task 完成实现或修复，THEN必须基于 fresh exact task delta 通过 task review 后才能 integration；每个 unified run 在 finish 前仍执行其 scope 对应的完整 plan/spec-level final-review。inline profile 的 checkpoint 频率可不同，但不得减少 final-review 六阶段责任。 |
| `AC-026` | WHEN facade migration 分阶段发布，THEN fresh alias 只按该阶段明确 routing matrix 创建 unified 或 current-contract run；recognized current-contract state 只进 frozen legacy engine；rollback 只停止 fresh unified selection，不把 active unified run 改写为 legacy，也不把 `concurrency=1` 伪装成 engine rollback。 |

## 6. Non-Functional Requirements

| Priority | 属性 | 验收底线 |
|---|---|---|
| `P0` | Absolute quality | 每个 fixture 的 expected outcome、Critical/Important recall、final tree 和 tests 全部正确。 |
| `P0` | Safety | nested delegation、write-root escape、source Git mutation、out-of-scope integration、stale approval、unrelated invoking-checkout mutation均为 0；事后检测不能替代写前强制边界。 |
| `P0` | Reliability | duplicate accepted result/review/integration/completion/cleanup 为 0；stale fence mutation 为 0；uncertain spawn 可检测，仅在原 worker terminal 后 replacement 有界。 |
| `P0` | Provenance | run/task/review 的 source、tree、artifact、requested/observed model、attempt、operation 和 reservation hashes 可验证。 |
| `P0` | Compatibility | existing public CLI/skill/install snapshots 与 current-contract resume fixture 全过，unknown generation fail closed。 |
| `P1` | Parallel latency | eligible DAG candidate 的 wall-time p50 相对 serial 改善至少 25%，p95 回归不超过 10%；同时报告 queue、worktree、review、retry 和 integration overhead。 |
| `P1` | Prompt efficiency | main-chain uncached input token p50 降低至少 30%，全 run total token p50 不回归超过 10%；仅在全部 P0 通过时计为改善。 |
| `P1` | Small-task overhead | 不符合 parallel eligibility 的小任务不因 unified startup 增加超过 10% wall time；超过时 policy 必须选择更轻的 isolated inline/serial profile。 |
| `P1` | Provider degradation | capacity/rate-limit 下 retry 有界，无重复接受工作或无界 polling；仅在原 worker terminal 后单 task replacement 默认不超过 1 次，reconciliation 继续最多 2 次。 |
| `P2` | Maintainability | 一个 constraint 一个 owner；共享行为由 schema/runtime tests 治理，不依赖重复 prose。 |

以上 P1 数值是 versioned candidate graduation thresholds，不是永久产品 SLA；policy 调整必须保留
`AC-023` 的单变量和 P0 absolute gates。性能 graduation 至少使用宽 DAG、长尾、diamond dependency
和 package fan-in 四类 workload；每类至少 20 个平衡 baseline-first/candidate-first paired samples，
方可报告 p95。

## 7. Supersession Authority

- 本合同替代 `.loopx/intake/2026-07-14-parallel-subagent-exec/requirements.md` 中要求
  parallel 永久作为独立 manual lane、所有 plan 永久携带 JSON metadata、固定 integration ordering、
  独立 state namespace 和 `subagent-exec` 永不参与统一 facade 的条款。
- 本合同只替代 `docs/loopx/design/2026-07-13-skill-suite-v2-reset/` 中“当前版本绝不保留
  相邻 generation engine”的 compatibility 选择；pre-v2 state 不支持、unknown schema fail closed、
  controller-only、leaf-only 和 shared evidence/review owner 继续有效。
- 2026-07-14 parallel 设计中的 worktree isolation、review-before-integration、controller-owned Git、
  CAS、strict resume、bounded reconciliation、package review、finish、cleanup ownership 和 dirty-worktree
  safety 默认 carried forward，除非详细设计的 clause matrix 明确给出 successor。

## 8. 明确 Deferred

- automatic risk/mode routing、automatic parallel 与 P=4 graduation。
- `wait-any` 之后的 critical-path priority、early integration 和 test layering，各自单独评估。
- low-risk wave review 或 compact gate 的任何责任缩减。
- fine-grained ref/resource lease、cross-process 强制锁、外部 Git writer coordination 和持久 queue。
- public mode/risk/explain CLI/JSON、固定 model ID、跨 repo capacity backend。
- adaptive in-place execution；若未来需要，必须重新设计可证明的 rollback/quarantine 边界。
- legacy engine 的删除日期；删除必须满足详细设计的 retirement Gate 并经过单独 compatibility review。

## 9. Handoff

本合同无未决 material requirement，状态为 `ready_for_spec`。详细设计必须保留完整
`AC-* -> D-* -> TC-*` 关系，并把 experimental threshold 与永久产品合同分开。
