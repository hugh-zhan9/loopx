# 用一次破坏性重置统一 loopx Skill Suite 当前合同

Author(s): loopx maintainers
Last updated: 2026-07-13
Status: Accepted
Discussion: 本次对话中的全量 skill 审计与用户批准
Source requirements: `docs/loopx/plans/2026-07-13-skill-suite-v2-reset/00-overview.md` 中的 `AC-001`–`AC-008`、`TC-001`–`TC-008`
Support lenses: architecture-designer, cli-developer

## Abstract / 摘要

我们选择一次性替换 loopx 的当前 skill、workflow state、agent topology、review/evidence 和治理合同。新版本不读取、迁移或兼容正在运行的旧 `.loopx` artifact；历史设计与计划继续保留为记录。所有 loopx 派发的 worker 都是 leaf worker，只有顶层 controller 可以管理 agent 生命周期。

## Background / 背景与动机

全量审计显示主链已经具备较强的 AC/TC → D → T → evidence → review → finish 追踪能力，但合同在长期 hardening 后出现重复、跨 skill 漂移和外围治理不足。实际运行中，主动委派模型会把缺少拓扑限制的 worker 继续拆成 subagent，并对异步等待进行高频轮询。CLI 的 clarify 下一步提示也没有持久化 `needs_spec` 与 `direct_to_plan` 的区别。

## Goals And Non-Goals / 目标与非目标

目标：统一 agent 所有权、workflow 路由、诊断与证据 schema、review 层级和 27 个 bundled skills 的语义治理；将 root skill 收敛为短而可执行的 orchestrator。

非目标：迁移旧 runtime state、兼容旧报告或 ledger、为历史计划改写文本、增加依赖、保留旧字段 alias 或 fallback reader。

## Proposal / 设计方案

1. 建立共享 agent topology、review ownership 和 evidence contracts。
2. workflow state 显式保存 clarify `handoff_decision`，CLI 只按该字段路由。
3. 核心 root skills 只保留 fast path、hard gates、状态转换和 reference routing。
4. `debug` 成为诊断生产者，`issue`/`fix` 消费同一 schema；TDD 不得删除用户或既有实现。
5. 修正 domain lenses 的事实错误和绝对规则，以仓库证据和已固定工具为优先。
6. 为所有 bundled skills 建立一对一语义治理矩阵。

边界：共享合同只约束当前 bundled skill surface，不试图治理第三方 skill 或历史文档。

## Support Lens Checks / 专项设计检查

| Support lens | Trigger | Design checks applied | Result |
|---|---|---|---|
| architecture-designer | workflow、state、安装与治理边界变化 | 所有权、失败恢复、单一事实源、可逆性 | 采用 current-contract reset 与单一合同 owner |
| cli-developer | `loopx next/status` 行为变化 | human/JSON 一致、稳定状态枚举、明确错误 | 持久化 `handoff_decision` 并拒绝旧状态 |

## Boundary Scenarios / 边界场景

- 缺失或非法 `handoff_decision`：拒绝并提示重建当前 workflow，不猜测下一步。
- worker 尝试再派发 agent：worker-visible prompt 明确禁止，治理测试阻止回归。
- agent 等待窗口为空：保持原 worker，不立即替换或催问。
- pre-v2 state：不迁移、不自动删除，返回 restart diagnostic。
- child plan 部分失败：保留 checkpoint，修复后从当前 child 恢复；不启动后续 child。
- 当前文档与历史记录冲突：当前 product paths 为准；历史目录不参与 negative assertion。
- 权限、多租户、数据库迁移：本项目是本地 CLI/skill suite，不涉及。

## Rationale / 理由与取舍

| Alternative | Why Not |
|---|---|
| 在现有合同上继续增量补丁 | 会继续复制规则和兼容分支，扩大模型注意力竞争 |
| 为旧 state 增加 migration | 用户明确不要求兼容，且会保留两套语义 |
| 只修 subagent-exec | 其他 reviewer/fixer dispatch 仍可产生嵌套 agent |
| 删除全部 references，做极短 prompt | 会丢失必要 schema、验证和平台差异；应采用按需 reference routing |

## Compatibility / 兼容性

这是 breaking change。pre-v2 运行状态、ledger、报告和 package state 不受支持；不提供 migration、feature flag、downgrade 或 fallback。安装命令、canonical `skills/` source 和历史 git/docs 记录保持不变。

## Operational And Security Impact / 运行与安全影响

发布前必须通过全量测试、skill verification 和 package dry-run。错误状态不得被自动删除。agent 数量由 controller-only topology 控制，降低并发写入和资源失控风险。

## Implementation And Transition / 实现与过渡

先落共享合同，再修改 runtime 路由，然后依次收敛核心 workflow、issue/support、domain lenses，最后补齐治理与公开文档。每个 child plan 独立 review 和提交。
