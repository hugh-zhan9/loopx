## 1. 背景与问题

四臂 benchmark 的结论：对前沿模型（gpt-5.6-sol），一份 33 行的 working
agreement 在停下纪律上与完整 v0.7 治理运行时打平（+65pp vs 裸模型），token
仅 1/3；能力三类任务全天花板；v0.7 运行时引入两处真实回归且整体更贵。宿主
原生能力（subagent/worktree/resume）已覆盖执行原语。结论：与宿主竞争执行是
输掉生态位；loopx 的不可替代价值在"产出并验证纪律文档"。

## 2. 目标与非目标

**目标**：产物是文档，执行归模型。保留 clarify + spec（交互过程 + 持久契约
产物），plan2exec 降级为文档 schema（agent 自己按文档执行），其余工作流与
运行时溶解为 working agreement 条款。

**非目标**：不改 eval 基础设施（drills / benchmark / 决策库是质检线，全部
保留）；不动支持 lenses 与 issue/fix 专项工作流；本次不做测试修复（依维护者
指示，审核后另行处理）。

## 3. 验收标准

- AC-01 working agreement 成为核心交付物：`templates/working-agreement.md`
  单一来源，安装期写入宿主 guidance 管理块，承载执行/评审/验证/停下/Git 全部
  纪律条款（含 benchmark 实证的边界条件与共享状态条款）。
- AC-02 canonical intents 收敛为 clarify / spec / plan2exec 三个文档产出
  skill；plan schema 去运行时化（无 profile、无执行图，附"执行规则"节供
  消费 agent 遵循）。
- AC-03 溶解且不留悬空引用：exec、subagent-exec、parallel-subagent-exec、
  review、final-review、fix-review、finish、每轮 hook 及 workflow-state
  运行时删除；retained skills（fix、plan-reviewer、lancet 等）与 src/ 中的
  引用全部改指 working agreement 或删除。
- AC-04 drills 被测契约改指 working agreement（四条核心保证的压测对象随
  产物迁移）。
- AC-05 治理一致性：RESOLVER、README（中英）、skills 文档（中英）、契约
  矩阵、package files 白名单、verify-skills 与新表面一致；被取代的决策记录
  标注 superseded_by 并新增 docs-first-pivot 记录。

## 4. 设计决策

- D-01 **单一来源**：working agreement 是文件（templates/），安装块从文件
  读取，不再维护第二份内联常量。
- D-02 **plan 是契约不是程序**：schema 保留 P-* slices/依赖/写作用域/验收/
  验证 + "消费 agent 执行规则"三条（依赖序执行、写作用域不相交才可并行、
  遵循 working agreement）；删除 profile 选择与执行图双写。
- D-03 **评审是条款不是管线**：高风险 diff 由宿主原生 subagent 独立评审；
  反预判禁令保留为条款文字（运行时守卫随 runner 删除，由 drills 场景
  review-gate-fail-closed 承接行为验证）。
- D-04 **CLI 不再推荐已删 skill**：next-skill 在完成态返回 null，doctor 把
  遗留已安装 hook 报为 legacy 待清理。
- D-05 **可证伪假设前置声明**：clarify/spec 对半模糊需求的增益、弱模型的
  编排收益，是 v0.8 的两个判决性实验（未实施）。
